## 1. 원고

## 2. 교정본 반영 조건(실제 코드 기준) — '규칙=자동, AI=불가'가 아니다

앱(`_getCorrections`)은 **편집자가 '해결됨'으로 표시한 지적만** 교정본에 넣는다. 그때도 다음을 모두 만족해야 한다: found가 본문에 그대로 있음 · 수정안이 지시문이 아닌 문장이고 원문과 다름 · noAutoReplace(긴·여러 줄 예시, 원문·수정안 불일치 가드)가 아님 · 조판·추출 단계가 아님 · 허용/제외되지 않음 · 현재 검사 기준 지문이 유효함. 규칙 지적이든 AI 지적이든 같은 조건이다. 단계(오류 교정/문맥 검토/선택적 윤문)는 화면의 기본 분류와 안내 문구를 바꿀 뿐 반영을 막지 않는다.

평가에서는 지적마다 **반영 경로**를 자동 판정한다: `해결됨 표시 시 교정본 반영` / `안내만(수정안 없음·지시문)` / `반영 불가(예시·참고용)` / `반영 불가(원문 불일치)` / `반영 불가(조판·추출 확인)`. **편집상 수락 가능성**(그대로 수락 / 손봐야 수락 / 거부)은 사람이 판정한다. 둘은 별도 열이다.

발견(보고만): 수정안 정리 규칙(`_cleanSuggestion`)이 'X (설명)' 꼴의 괄호를 떼므로 **영문 병기 복원 수정안('요청 문장(prompt)')은 교정본에 들어갈 때 영문이 빠진다**. 채점기는 이를 '수정안 정답·반영 시 손실(사람 검토)'로 따로 센다.

## 3. 엄격 탐지 정의(자동 판정)

| 단계 | 조건 | 성공 여부 |
|---|---|---|
| 정확 수정 | 앱의 정리 규칙을 거친 수정안을 적용하면 정답 표기로 돌아옴(비문·사실은 accept 핵심어 포함도 인정) | 성공 |
| 설명 겨냥 | 지적의 설명·수정안이 심은 오류 문자열·정답 문자열·오류에만 있는 토큰(예 '15:12', '훌적')을 직접 언급, 또는 found가 오류 문자열 **안**의 조각(예 규칙이 '~에 있어서'만 집음) | 성공(탐지) |
| 수정안 정답·반영 시 손실 | 수정안 원문은 정답이나 정리 규칙을 거치면 정답이 아님 | 사람 검토 |
| 겹침만 | 문장·표 행 전체를 잡은 지적이 오류 구간과 겹치기만 함(설명에 문장이 인용돼 있어도 제외) | 사람 검토(자동은 미탐) |
| 미탐 | 겹치는 지적 없음 | 실패 |

found가 오류 문자열을 **포함**하기만 한 것은 성공으로 치지 않는다. 느슨(겹침) 기준은 참고로만 병기한다.

## 4. 오지적률 2종

- **정상 문장 오지적률** = 정상 문장을 바꾸자는 지적(수정안이 원문과 다름)이 붙은 정상 문장 수 ÷ 정상 문장 수(15). 수정안 없는 안내(조사중복·주어과다 검토)는 '사람 검토'로 따로 센다.
- **전체 지적 중 불필요 지적 비율** = 상한은 (정상 문장에 붙은 지적 + 심지 않은 곳 지적) ÷ 전체 지적(편집 완료 원고 가정). 심지 않은 곳 지적은 사람이 실제 오류/취향·스타일/오지적/중복으로 분류한 뒤 확정한다. 단계·반영 경로를 함께 표시한다.
- 정상 조사 반복(N1·N2·N6·N11)과 단어 내부 문자열(N3·N4)은 종류별로 별도 집계한다.
